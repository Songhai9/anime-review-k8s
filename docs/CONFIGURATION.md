## Bootstrap AWS identity

On the control plane, AWS CLI uses the instance profile unless another identity is explicitly configured. SSM does not forward the GitLab runner's role to the machine. **However, `AmazonSSMManagedInstanceCore`, which Terraform attaches to the control plane, already includes `ssm:GetParameter` and `ssm:GetParameters` on `*`.** It would therefore be incorrect to infer missing Parameter Store access merely from the absence of a dedicated role policy. Check effective IAM/SCP restrictions and KMS permissions. [Official AWS policy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/AmazonSSMManagedInstanceCore.html).

Bootstrap must be able to execute AWS CLI; the infra playbooks do not ensure its installation. The parameter must exist in the specified region. A customer-managed KMS key requires appropriate `kms:Decrypt` permissions and a key policy compatible with the identity actually executing the command.

## GitLab tokens

Application CI publishes images with its built-in registry variables. For durable worker pulls, prefer a `read_registry` deploy token over an ephemeral job token.

For the cross-project trigger, add the app project to the K8s project's allowlist and verify the triggering user's permissions. For the commit inside K8s, enable **Allow Git push requests to the repository** in its job-token permissions. The job runs inside that project and uses its own token. Protected `main` rules must permit the push for the relevant identity. A push with this job token does not start another pipeline; the existing pipeline's deploy job continues delivery. [GitLab documentation](https://docs.gitlab.com/ci/jobs/ci_job_token/).

YAML does not create these GitLab settings. Their effective values were not inspected through the GitLab UI during preparation of this documentation.

## Supplied examples

- `deployment.env.example`: non-secret operator variables; copy outside Git and adapt.
- `registry-serviceaccount.yaml.example`: optional manifest linking the pull Secret to the default ServiceAccount after Secret creation. This addition is not part of the historical implementation.

Do not commit a manifest containing a real SQL password or token in plaintext. Base64 encoding of Kubernetes Secrets is not encryption; this repository does not establish that etcd Secret encryption is enabled.
