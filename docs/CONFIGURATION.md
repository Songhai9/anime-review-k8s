## Where each value lives

| Item | Location | Value / source |
|---|---|---|
| Backend image | `charts/anime-review/values.yaml` → `backend.image.repository` / `.tag` | `registry.gitlab.com/<group>/<app>/backend`, tag = app short SHA |
| Frontend image | `values.yaml` → `frontend.image.*` | same tag as the backend |
| Replicas, resources, ports | `values.yaml` → `backend`, `frontend`, `postgres` | defaults: 2 / 1 / 1 replicas |
| API address for the frontend | `frontend-deployment.yaml` → `API_URL` | `http://backend:3001` |
| SQL host / port / db / user | `values.yaml` → `backend.database.*`, `postgres.*` | `postgres:5432`, `postgres_db`, `postgres_user` |
| SQL password | SSM Parameter Store `/anime-review/postgres/password` | SecureString, `eu-north-1`, created once by you |
| Kubernetes Secret | `postgres-secrets`, key `POSTGRES_PASSWORD` | generated by `bootstrap-cluster.sh` |
| PVC | `values.yaml` → `postgres.storage` | `gp3`, `8Gi` |
| Ingress / policies | `values.yaml` → `ingress.enabled`, `networkPolicies.enabled` | `true` |
| Add-on chart versions | `install_addons.sh` | EBS CSI 2.66.0 · ingress-nginx 4.15.1 · metrics-server 3.14.0 |
| NodePorts | `addons/ingress-nginx/values.yaml` | 30080 / 30443 (must match the NLB target groups) |
| Registry pull Secret | `gitlab-registry` + default ServiceAccount | only for a private registry |
| CI AWS role | GitLab variable `AWS_ROLE_ARN` | infra output `k8s_cd_arn` |
| Transfer bucket | `.gitlab-ci.yml` → `K8S_TRANSFER_BUCKET` | infra `k8s_transfer_bucket_name` |
| Region | `.gitlab-ci.yml`, `bootstrap-cluster.sh` | `eu-north-1` (hard-coded) |
| Control plane lookup | `.gitlab-ci.yml` EC2 filter | tag `Name=anime-review-control-plane` |
| Image tag from app CI | `IMAGE_TAG` | forwarded by `trigger_k8s` |
| Revision to deploy | `DEPLOY_SHA` | dotenv artifact of `update_manifests` |

On GitLab, `BACKEND_IMAGE` / `FRONTEND_IMAGE` / `*_REPOSITORY` are forwarded but ignored: only tags change. On GitHub, `deploy.yml` writes both the repository and the tag it receives (`ghcr.io/<owner>/anime-review-{backend,frontend}`).

## AWS identities

| Identity | Used by | Permissions (Terraform, infra repo) |
|---|---|---|
| `k8s-cd` role (OIDC, GitLab + GitHub) | `deploy_cluster` job / `deploy` workflow | `ec2:DescribeInstances`; `s3:PutObject/DeleteObject` on `k8s-bootstrap/*`; `ssm:SendCommand` (`AWS-RunShellScript`) + status reads |
| Control-plane instance role | the script run by SSM, `bootstrap-cluster.sh` | `AmazonSSMManagedInstanceCore`; `s3:GetObject` on `k8s-bootstrap/*`; `ssm:GetParameter` on `/anime-review/postgres/password` |
| Worker instance role | EBS CSI driver (IMDSv2, hop limit 2) | `AmazonEBSCSIDriverPolicyV2`, `AmazonSSMManagedInstanceCore` |

The runner's role is never forwarded to the node: commands executed by SSM use the node's instance role. The trust policy of `k8s-cd` accepts only `project_path:anilist-cicd/anilist-k8s:ref_type:branch:ref:main`; update it in the infra repository if you rename the project.

## GitLab tokens and permissions

- **Cross-project trigger:** in this project, *Settings → CI/CD → Job token permissions*, add anime-review-app (image deliveries) and anime-review-infra (bootstrap). The triggering user also needs permission to run pipelines here.
- **Commit from CI:** same page, enable *Allow Git push requests to the repository*. `update_manifests` pushes with `CI_JOB_TOKEN`; the protected `main` branch must accept it. A push made with the job token does not start a new pipeline, so the same pipeline continues with `deploy_cluster`.
- **Image pulls:** public images need nothing. For a private registry, use a `read_registry` deploy token (durable) rather than a job token (expires with the job).

## Supplied examples

| File | Copy to | Purpose |
|---|---|---|
| `examples/deployment.env.example` | outside Git, `source` it on the control plane | shell variables used by the manual commands |
| `examples/helm-values.yaml.example` | outside Git, pass with `-f` | override replicas, resources, images for a manual `helm upgrade` |
| `examples/registry-serviceaccount.yaml.example` | `kubectl apply -f` after creating `gitlab-registry` | attach the pull Secret to the default ServiceAccount |
| `examples/gitlab-ci-variables.env.example` | nowhere: checklist for GitLab settings | CI variables and permissions |
| `examples/github-actions.env.example` | nowhere: checklist for GitHub settings | variables, branch protection, callers' PAT |
| `examples/bootstrap-job.gitlab-ci.yml.example` | append to `.gitlab-ci.yml` | proposed job handling `BOOTSTRAP_CLUSTER=true` |

Never commit a manifest containing a real password or token. Kubernetes Secrets are only base64-encoded; this cluster does not enable etcd encryption at rest.
